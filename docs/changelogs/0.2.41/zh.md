## v0.2.41

### 修复

- **macOS 注音 / 仓颉 / RIME / 搜狗 / 百度 输入法下整段粘贴失效**：使用上
  述输入法时，OpenSpeech 转录完成后无法把整段文字粘贴到目标应用——表现是
  屏幕上出现一个反色高亮区（看着像「全选」），但文档里没有任何字落地，
  必须手动 Ctrl+V 才能拿到内容。0.2.40 的尝试性修复（粘贴前发右方向键）
  对注音这类强组字输入法不够。本版改为粘贴时短暂切到英文键盘布局（约
  100 毫秒）让 Cmd+V 直达应用，粘贴完立刻切回原输入法；切换过程不会
  影响输入法图标显示。如果你之前每条录音都要手动粘贴，升到本版应当
  恢复自动落字。
  - 不在上述名单的输入法（如苹果简中拼音、纯键盘布局）行为完全不变。

### 新增

- **历史记录可以加星收藏**：在听写卡片或 History 页右上角点星标按钮，
  即可把一条记录标为收藏。History 页 filter 栏新增「收藏」tab，可以
  只看收藏过的内容。
- **History 行内播放控件常驻**：之前播放/暂停按钮只在鼠标 hover 时
  才显示，正在播放中用户找不到暂停按钮就只能等放完。本版只要这一行
  处于播放或暂停态，控件就一直显示。

### 改进

- **AI 整理对「正文长且具体 + 历史话题相邻」的场景更稳**：之前一种
  失败模式是——用户说一段完整、自带动作动词的请求（例如「给我一段
  终端命令清空所有权限然后让用户重装」），但因为 ConversationHistory
  里恰好聊过相邻话题（权限管理 / 启动检查 / 之类），AI 会去 history
  翻措辞把正文整段替换成 history 里某句别的 ask，原本要发出去的具体
  方案被丢掉。本版给 AI 整理新增了针对这种「长正文 + history bleed」
  的反面例子（zh-CN / zh-TW / en 三语种），把 history 限定为「只供
  解析指代和领域偏向，永远不能拿 history 的句子来重新表达正文」。
